# The GPU renderer

The plan to draw the world from meshes kept on the GPU instead of from the
triangles the game's code builds every frame, and the record of the work against
it. Started 2026-09-28 on the branch `retained-world`. **Step 0 is in; nothing of
the renderer itself is built yet.**

## Why: the frame is the game's geometry, done on one CPU thread

Everything already *rasterizes* on the GPU. What runs on the CPU is making the
triangles: the game's renderer (stage 13, recompiled, most of it now C#) walks the
map, transforms every vertex through the emulated GTE one at a time, clips,
assembles and lights each polygon, writes a GP0 packet into guest RAM and links it
into the ordering table; `DrawOTag` then decodes each packet and recovers what the
packet threw away (depth, sub-pixel fraction, lighting, texture rectangle,
material) through four side tables, and copies the vertices into a GL buffer.

Measured at the `KF2_AUTOSTART=new` spot facing the pool, render scale 5, 16:9,
`KF2_FPS=1000 KF2_PROFILE=1`, planar reflections off (see "What the planar walk
costs, and where" in `docs/RENDERING.md` for the run):

| | ms/frame |
|---|---|
| map tile walk (transforms, clipper, assemblers) | 1.47 |
| `DrawOTag` (packet walk, side-table lookups, batching) | 0.98 |
| object walk and the lit assembler | 0.25 |
| present (swap, AO, surface buffer, composite) | 0.46 |
| camera block, HUD, the rest | ~0.25 |
| **frame work** | **3.44** |

Stage 13 is 3.42 ms of the 3.44; the game's logic runs at 20 Hz and barely
registers. About 2.5 ms of it is the world's geometry. **Every extra view pays it
again**: the planar walk re-runs the tile walk and the mirrored `DrawOTag` and
replays the model submits, +2.1 ms a frame (290 fps to 179). A shadow cubemap, a
second plane or a longer render distance each scale the same way.

The fix is **retained-mode rendering**: the scene kept on the GPU, the CPU saying
each frame only what changed and what is visible. In emulation terms it is HLE of
the game's own renderer. The port already has the start of it: the retained scene
(`0072`, "The retained scene" in `docs/RENDERING.md`) builds the map into
world-space triangles on the GPU, each corner within 1 px of the GTE's, lit per
face as the assembler lights it, fogged per corner from the record's DQA, DQB and
curve, and drawn through `WorldVs` from any camera.

## The target

**Drawn by the GPU renderer**: the whole world. The map, every model (creatures,
objects, doors, props, billboards, effects), the first-person arm and the other
view-space models, from every camera the port wants: the eye, the mirror, the
lights' shadow cubemaps, a camera cubemap, a menu's redraw.

**Still drawn from the game's packets**: the game's 2D. The HUD, menus, shops,
message boxes, fades and flashes, the loading screen, the MDEC movies, `OPEN.EXE`
and `END.EXE`. That is generated by code, not data, so there is nothing to keep on
the GPU; it is about 0.25 ms of the frame, rasterized on the GPU already, and
depth-tested against the world. **Open**: whether any `fdat` module draws 3D
through a routine of its own outside the two walks; a census is needed before the
old path is switched off.

**What the game's walks still do**: decide. The tile walk's sweep (0.013 ms when
it only enumerates) says which halves are visible; the object walk still runs for
its side effects (ambient sounds, texture page uploads, the billboard clock) and
says which models are live, where, and in which pose.

**Estimated** (not measured): world frame work from ~2.5 ms to well under 1, and
an extra view close to zero on the CPU.

## The steps

Each ships behind a switch and is judged before the next starts. The old world
path stays as an env-var comparison throughout, and afterwards (see "The old path
stays as the comparison").

### Step 0: time the GPU

Only CPU time is measured. `0046` has `GL_TIME_ELAPSED` queries, but only while
the frame viewer has a trace sink, and the viewer skips the mirrored draw. Before
the CPU cost moves, the profiler needs a GPU time per frame and per pass (the
frame's batches, a capture, AO, the reflection pass, the composite), so there is a
budget to move it into.

**Done** (`0084`; "GPU time per present" in `docs/DEVELOPMENT.md`). At the same
spot, render scale 5, SSAO, murk and waves on, RX 9070 XT:

| | planar off | planar on |
|---|---|---|
| CPU frame work | 3.34 ms | 5.85-5.95 ms |
| GPU per present | 1.46 ms | 1.50 ms |
| of it: scene | 0.89-1.03 | 0.90 |
| capture (the mirror) | - | 0.18 |
| AO | 0.25-0.27 | 0.25 |
| reflection pass | 0.02 | 0.02 |
| composite | 0.14-0.15 | 0.14 |

**The GPU is idle three quarters of the frame**, and the mirror costs it 0.18 ms
against the CPU's 2.1 ms. Moving the world's geometry onto it has room: at these
numbers the GPU alone would allow about 650 fps. The vertex work the renderer adds
is not in these figures, since today the GPU is handed finished screen positions.

### Step 1: the map, instanced, for the main view

The map is 80x80 tiles of two halves, and a half names a mesh of the area's model
bank, a height, a quarter turn and a light record. So a mesh is stored once and
drawn once per half that uses it (instancing), each copy placed by a per-half
record on the GPU: tile, height, turn, light record, material, flags. The game's
cull becomes a mask over those records (the retained scene's `uHalves` already is
one). The retained scene's chunk bounds (8x8 tiles) keep the draws few.

A tile the game rewrites while it runs, and a remaster `Level` edit, becomes a
record update rather than the 5.5-7.5 ms rebuild the retained scene does today.

Checked against the old path by `snap` hash and a per-pixel difference, then by
eye.

### Step 2: every map feature in the renderer

What hooks the tile packets today, and has to work the new way first:

- `EvenFog`: the fog and light blend between the records of neighbouring tiles.
- Per-pixel lighting (`0048`): the records the lit colour is made from.
- `WaterSwell`: moves the water's interior vertices; a vertex-shader function of the same field.
- The remaster's materials per half and per face, lights, fog colour, sky, darkness.
- `RenderDistance`: a larger mask, and no 15-tile cap (the s16 placement is the game's, not the GPU's).
- AO and the reflection pass's surface buffer (`0058`, `0067`): fed from the renderer's draws, not `DrawTri`.
- `BlendOrder` (`0079`): an opaque pass, then the blended one.
- `EnhancementDistance` (`0083`), the fluid scroll (`0053`), the mip atlas (`0060`), texture replacement (`0073`).

Free with float vertices and a depth: perspective correction, sub-pixel,
the Z-buffer and its records, the backface and facing culls.

### Step 3: models

A mesh cache: each model uploaded once when it becomes resident, invalidated when
the loader evicts it (`PlanarWalk.Resident` is the test). Each frame an instance
record per live model: matrix, light matrix, depth cue, blend, pose. First the
pose stays the game's (the posed vertex base is uploaded); blending the keyframes
on the GPU follows, and `AnimSmoothing`'s in-between poses then cost nothing. The
arm and view-space models are models too.

### Step 4: the old world path off

The walks stop building triangles. `PolyAssembler`, `TileWalk` and `ModelWalk`
keep their enumerating halves; the assembling halves run only under the
comparison.

### Step 5: every extra view on the same renderer

Reflections (below), the authored lights' shadow cubemaps (`0077`, already drawn
from the retained map; all six faces in one pass by layered rendering), a camera
cubemap, `MenuWorld`'s and `LoopPacing`'s redraws (a draw call each), and the
smoothers (interpolated instance records instead of rebuilt geometry).

### Step 6, if needed: culling on the GPU

A compute pass over the chunks and halves building the draw list. Worth it only if
the render distance grows well past the game's window; the CPU cull is cheap.

## Where the reflections come in

**The planar walk's rules carry over; only where its geometry comes from changes.**
Decided 2026-09-28: the planar walk is the reflection ("The planar walk is the
reflection, with a cull of its own" in `docs/RENDERING.md`). What it decides stays:

- the camera mirrored by position (`Y' = 2h - Y`), pitch and roll negated, the
  last flip done by the pass reading row `2·OFY - y`;
- `PlanarCull`'s set of halves: the game's cells, then every half on the eye's
  level inside the cone widened for the pitch, with no occlusion flood;
- mirror-only models, admitted by that cull;
- the clip plane (`uClipPlane`, the bias) and the level fog (`uClipLevel`);
- the plane found from the water the backend classifies, at the rest height;
- the planar texture on the target, and `SsrFs`'s `planarAt` reading it, with the
  empty-texel rule.

What goes: the second tile walk, the replayed submits and the mirrored `DrawOTag`.
The mirror becomes the renderer drawn from the mirrored camera with
`PlanarCull`'s mask, into the same planar texture, so the reflection pass does not
change at all. The retained scene's own reflection code (`GlRetained`'s planes and
cubemap, the half gate, `WorldVs`) is the renderer's ancestor and folds into it;
its `KF2_RETAINED` switch is retired then.

**When.** The mirror is the renderer's second consumer, not its first: it moves
once Step 2 has the map at parity (Step 5 in full). It can move earlier as a
proving ground, since a difference in the water is easier to live with than one in
the picture: after Step 1 and the map features the water shows (fog, the swell,
materials), with the models still replayed through the game's code until Step 3.
That takes about 1.9 of the planar walk's 2.1 ms off before the main view
switches.

The retained scene's reflections were judged worse than the planar walk with the
eye's cull as their gate (2026-09-26), and the likely reason is that gate:
the mirror saw places the eye's flood culled. Driving the renderer with
`PlanarCull`'s mask is the test of that reading.

## The old path stays as the comparison

The GPU world is within 1 px of the game's output, not bit-identical, so the only
way to catch a regression (a half missing, a light subtly wrong) is to draw the
old way and compare. It is the same reason `KF2_POLYASM=verify` exists. It is
also the fallback where the renderer cannot run: it is GL core only, and the
runtime keeps a GLSL 1.20 backend and a software rasterizer (the frame viewer's).
The frame viewer loses the world command by command under the renderer; it keeps
the 2D.

## Rules this keeps

- The mechanism measured and the picture judged are separate; ship off until
  judged.
- The walks' side effects are the game's and keep running.
- No gameplay change: collision, the map block and saves are untouched
  (`savecheck`).
- A new runtime mechanism gets a new patch number; a fix to one amends it.
